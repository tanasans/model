# モデルルーム 無人見学予約システム

さくらインターネットのレンタルサーバー（PHP）上で動く、無人モデルルームの見学予約システムです。
お客様がフォームから日時とアンケートを送信すると、二重予約を確認したうえで予約を確定し、
**その予約時間帯だけ有効な入室パスコード**を SwitchBot のスマートロック（キーパッド）に登録して、
メールでお知らせします。顧客情報とログは Google スプレッドシートへ自動で転記されます。

---

## 1. 全体の流れ

```
お客様（スマホ）
   │ ① 空き枠を表示（api/slots.php）
   │ ② 日時＋お客様情報＋アンケートを送信（api/reserve.php）
   ▼
さくらのサーバー（PHP）
   │ ③ 二重予約チェック（SQLiteのUNIQUE制約で確実に1件だけ通す）
   │ ④ 6桁パスコードを生成
   │ ⑤ SwitchBot API に「有効期限付きパスコード」を登録  ──→ 玄関のキーパッド
   │ ⑥ お客様へパスコードをメール／管理者へ通知メール
   │ ⑦ 予約内容とログを Google スプレッドシートへ転記
   ▼
当日：お客様がキーパッドに6桁を入力 → 解錠（予約時間帯のみ有効）
終了後：cron が自動でパスコードを削除
```

### なぜ「時間になったら鍵を開ける」ではなく「期限付きパスコード」なのか

当日サーバーやネット回線、ハブが落ちていると解錠できず、お客様を締め出してしまいます。
パスコードは**登録した時点でロック本体が有効期限を覚える**ため、当日の通信状態に関係なく、
その時間帯だけ解錠でき、時間外は番号を打っても開きません。無人運営ではこちらが安全です。

## 2. サーバーもSwitchBotも使わずに動作確認する

実機を買う前・サーバーに上げる前に、動きだけを確かめる方法が3通りあります。

### 方法A：GitHub Pages にデモを置く（一番手軽・人に見せられる）

`demo/` フォルダに、**ブラウザの中だけで動く擬似サーバー**を用意してあります。
PHPもSwitchBotも不要で、予約の流れ・二重予約のはじき方・パスコードの有効時間まで確認できます。

1. このフォルダをそのままGitHubのリポジトリにアップロード（**`.gitignore` があるので設定ファイルは上がりません**）
2. リポジトリの Settings → Pages → Source を `main` ブランチの `/ (root)` にする
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` が開けます

| ページ | 内容 |
|---|---|
| `/`（トップ） | 案内と、試していただきたい手順 |
| `/demo/index.html` | **本番とまったく同じ予約フォーム**（`public/assets/app.js` をそのまま読んでいます） |
| `/demo/console.html` | デモ管理卓。メール文面・登録されたパスコード・予約一覧・ログが見られ、**玄関のキーパッドを模した画面**で解錠を試せます |
| `/demo/cancel.html` | お客様ご自身のキャンセル画面。管理卓のメール本文にあるリンクから開けます |

デモで確認できること:

- 空き枠の表示、予約の流れ（日時→入力→確認→完了）
- **同じ枠をもう一度予約するとエラーになり、空いている時間の候補が出る**
- お客様に届くメールの文面（実際には送られません）
- **キーパッドに6桁を入れたときの判定**。「試す日時」をずらすと、予約時間の前後では開かないことが確認できます（前後10分の余裕つき）
- **お客様ご自身のキャンセル**（メール文面のリンクをクリック → 確認画面 → 実行）
- 予約を取り消すと、そのパスコードが無効になり枠が戻ること

デモのデータはブラウザのローカル保存領域にだけ入ります。管理卓の「初期化」でいつでも消せます。
PCでもスマホでも開けるので、社内で回して見ていただくのにも使えます。

#### 打ち合わせの場で仕様を決める「設定を試す」パネル

デモ管理卓のいちばん上に、**その場で設定を変えて見せられるパネル**があります。
依頼者と画面を見ながら決め、決まった内容をそのまま本番へ持っていけます。

変えられるのは次の項目です。

| 項目 | できること |
|---|---|
| 1枠の長さ | 30分／45分／1時間／1時間30分／2時間 |
| 受付開始・終了 | 営業時間を入れると枠を自動で組み立てます |
| 昼休み | 開始・終了を入れると、そこにかかる枠を作りません（空欄なら通し） |
| 定休日 | 曜日のチェックを外すだけ |
| 何時間前まで受付 / 何日先まで受付 | 直前予約の制限と受付期間 |
| ご来場人数の上限 | |
| 解錠の前後余裕 | 何分前から／何分後まで開けられるか |
| アンケートの設問 | 文言の修正、選択肢の変更、必須の切り替え、**設問の追加・削除** |

「この設定で試す」を押すと予約フォームの見え方がすぐ変わるので、
「30分枠だとこう見えます」「水曜定休にするとこうなります」とその場でお見せできます。

決まったら **「設定の書き出し」** を開き、表示された内容を `app/config.php` に貼り付ければ本番に反映できます。
打ち合わせの結果をそのまま設定ファイルにできるので、聞き間違いや転記漏れが起きません。

受付期間を60日より先にすると、**SwitchBotのパスコード上限**についての注意が画面に出ます
（その場合は「予約時に登録」から「前日のcronでまとめて登録」へ作りを変える必要があります）。

「初期設定に戻す」でいつでも元に戻せます。設定はブラウザに保存されるので、
デモデータを初期化しても設定のほうは残ります。

> **注意**：デモは `demo/demo-api.js` の中に本番と同じ判定ルールを書き写したものです。
> `config.php` を直接変えたときは、デモ側の `CONF`（ファイル冒頭）も直さないと表示が食い違います。
> 上の「設定を試す」パネルで変えるぶんには、この心配はありません。
> デモに合わせて本番が変わることはありません（`public/` のファイルには手を加えていません）。

### 方法B：PHPを手元で動かす（本物のコードを試す）

本体のPHPそのものを確かめたい場合は、Windows用のPHPを展開するだけで動きます（インストール不要）。
PHPは公式サイトで無償配布されており、zipを解凍するだけで使えます。

1. **<https://www.php.net/downloads>** を開き、「I work with **Windows**」→「**ZIP Downloads**」を選ぶ
   （以前の `windows.php.net` はこのページに移っています）
2. 一覧から **VS17 x64 Non Thread Safe** の「Zip」をダウンロードし、例えば `C:\php` に展開
   - 2026年9月現在の最新は PHP 8.5.10、サイズは約34MBです
   - `php -S` で使うのは**Non Thread Safe（NTS）**のほうです。Thread Safe はApacheに組み込むとき用です
   - 動かすには Microsoft の **Visual C++ 再頒布可能パッケージ（2015-2022 x64）** が必要です。
     起動時に `VCRUNTIME140.dll がない` と出たら、これを入れてください
3. `C:\php\php.ini-development` を `php.ini` にコピーし、次の行の先頭の `;` を消す
   ```
   extension_dir = "ext"
   extension=curl
   extension=mbstring
   extension=openssl
   extension=pdo_sqlite
   ```
4. `app/config.php` で `switchbot.enabled` を `false`、`sheets.enabled` を `false` にする
5. コマンドプロンプトで、このフォルダに移動して簡易サーバーを起動

   ```bash
   C:\php\php.exe -S localhost:8000 -t public
   ```
6. ブラウザで `http://localhost:8000/` を開く（管理画面は `http://localhost:8000/admin/`）

この状態だと、**二重予約チェック・SQLiteへの保存・パスコードの生成・管理画面**まで本物のコードで動きます。
SwitchBotへの登録とスプレッドシート転記だけが「やったことにする」動きになります。
メールは送られません（送信結果は `storage/php-error.log` に出ます）。

### 方法C：さくらに上げて、鍵だけ止めておく

サーバーには上げてよいが実機がまだ、という段階では、`switchbot.enabled` を `false` のままにしてください。
メール送信とスプレッドシート転記は本物どおりに動き、パスコードの登録だけが行われません。
実機が届いたら `true` に変えるだけで切り替わります。

## 3. 必要なもの

| 項目 | 内容 |
|---|---|
| サーバー | さくらのレンタルサーバー（スタンダード以上）。PHP 8.0 以上、SQLite・cURL・OpenSSL・mbstring |
| 機器 | SwitchBot ロック（またはロックPro）＋ SwitchBot キーパッド／キーパッドタッチ＋ SwitchBot ハブ（API利用に必須） |

> **ハブについて**：SwitchBot のクラウドAPIを使うには、ロックがハブ（ハブ2 / ハブミニ等）経由で
> インターネットにつながっている必要があります。モデルルームにWi-Fiがない場合は、
> ポケットWi-FiやホームルーターなどWi-Fi環境を先にご用意ください。

## 4. 設置手順

### 4-1. ファイルを置く

さくらのファイルマネージャーかFTPで、次のように配置します（`modelroom` の部分は任意）。

```
/home/アカウント名/www/modelroom/
    app/        ← 公開しない（.htaccess で遮断済み）
    bin/        ← 公開しない
    storage/    ← 公開しない・書き込み可(707 または 755)
    public/     ← ★ここをサブドメインの公開フォルダに指定する
```

さくらのコントロールパネル →「ドメイン/SSL」→ サブドメイン `yoyaku.forest-v.jp` を追加し、
**公開フォルダに `www/modelroom/public` を指定**します。無料SSLも有効にしてください。

`storage` フォルダはパーミッション **707**（さくらの場合）にしておきます。

### 4-2. 設定ファイルを作る

`app/config.sample.php` をコピーして `app/config.php` を作り、値を入れます。
（同梱の `app/config.php` はコピー済みなので、そのまま編集しても構いません）

- `site.base_url` … `https://yoyaku.forest-v.jp`
- `booking.start_times` … 見学枠の開始時刻。**30分枠に変えたいときはここと `slot_minutes` を直すだけ**
- `mail.from` … さくらで作成した送信元アドレス（SPFが通るドメインのもの）
- `switchbot.*`、`sheets.*` … 下記 4-4 / 4-5 で取得した値

### 4-3. セットアップ点検

`storage/SETUP_ENABLED` という空ファイルを作ってから、
`https://yoyaku.forest-v.jp/setup.php` を開きます。

PHP拡張・書き込み権限・データベース作成・SwitchBot接続・メール送信をその場で点検できます。
同じ画面で**管理画面パスワードのハッシュ**も作れるので、生成された文字列を
`config.php` の `admin.password_hash` に貼り付けてください。

> **終わったら `storage/SETUP_ENABLED` を必ず削除してください。** 削除するとこのページは開かなくなります。

### 4-4. SwitchBot の設定

1. SwitchBot アプリ →「プロフィール」→「設定」→「アプリバージョン」を10回タップ → 開発者オプションが出ます
2. 「トークンを取得」でトークンとシークレットキーをコピー → `config.php` の `switchbot.token` / `secret` へ
3. デバイスIDは、同じ開発者オプションの一覧、または管理画面の「SwitchBot接続テスト」で確認できます。
   **キーパッドではなく「ロック本体」のIDを指定してください。**
4. `switchbot.key_type`
   - `timeLimit`（既定）… 予約時間帯の間は何度でも出入りできる。お手洗いなどで一度出ても再入室できるので推奨
   - `disposable` … その時間帯で1回だけ。一度出ると再入室できません

まずは `switchbot.enabled` を `false` にしたまま予約テストを行い、メールの文面や流れを確認してから
`true` にすると安全です（`false` の間はパスコードを生成するだけで、実際のロックには登録しません）。

### 4-5. Google スプレッドシートの設定

1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作成
2. 「APIとサービス」→ **Google Sheets API** を有効化
3. 「認証情報」→ サービスアカウントを作成 → キー（JSON）を作成してダウンロード
4. そのJSONを `storage/google-service-account.json` としてアップロード（公開フォルダの外なので安全です）
5. 記録用のスプレッドシートを新規作成し、**JSON内の `client_email`（〜@〜.iam.gserviceaccount.com）を編集者として共有**
6. スプレッドシートURLの `/d/` と `/edit` の間の文字列を `config.php` の `sheets.spreadsheet_id` へ
7. 管理画面の「スプレッドシート初期設定」を1回押すと、「予約」「ログ」シートと見出し行ができます

### 4-6. cron を登録する

さくらのコントロールパネル →「スクリプト設定」→「CRON設定」で、**5分おき**に次を実行します。

```
php /home/アカウント名/www/modelroom/bin/cron.php
```

（実行時間の欄：分 `*/5`、時・日・月・曜日はすべて `*`）

cron は次を行います。

- 終了した見学のパスコード削除と締め処理
- SwitchBot／メール／スプレッドシート連携が失敗したぶんの再試行
- ログのスプレッドシート転記
- **翌日の予約のリマインドメール**（毎朝9時台の実行時のみ）

## 5. 日々の運用

### 予約フォーム
`https://yoyaku.forest-v.jp/` … このURLを会社サイトやチラシのQRコードに載せます。

### 管理画面
`https://yoyaku.forest-v.jp/admin/` … 設定したパスワードでログインします。

- 予約一覧（今後／過去／すべて）とアンケート回答の確認
- **パスコード再発行**（発行に失敗したとき、お客様が番号を紛失したとき）
- **ご案内メールの再送**
- **予約の取消**（確認画面をはさみます。実行すると発行済みパスコードも無効化されます）
- **受付停止の登録**（臨時休業、社内利用で貸し切る時間など。終日・時間帯どちらも可）
- SwitchBot接続テスト／スプレッドシート初期設定

### お客様側のキャンセル

ご案内メールの末尾に、お客様ごとの専用リンクが入っています。

```
■ ご予約の変更・キャンセル
  こちらから承っております。
  https://yoyaku.forest-v.jp/cancel.php?code=K7QM-3B8T&t=8f3a…（お客様ごとに異なります）
```

このリンクを開くと予約内容が表示され、「このご予約をキャンセルする」→ 確認画面 → 確定、の順で
お客様ご自身がキャンセルできます。**ログインもパスワードも不要です。**

- URLに入っている `t=` は予約ごとに違う長い合言葉で、他人のURLを推測して開くことはできません
- キャンセルと同時に**入室パスコードが無効**になり、その枠はすぐ予約可能に戻ります
- お客様にはキャンセル完了メール、管理者には通知メールが届きます
- **開始時刻を過ぎるとこの画面からは取り消せません**（「お電話にてご連絡ください」と表示されます）
- 日時の変更機能はありません。いったんキャンセルして取り直していただく形です
- お客様がメールを紛失された場合は、管理画面から取り消すか、「メール再送」で同じリンクを送り直せます

## 6. 二重予約が起きない仕組み

1. **フォーム表示時**：予約済み・休業日・受付停止・直前すぎる枠は選べない形で表示します
2. **送信時**：サーバー側でもう一度同じ判定を行います
3. **登録時**：データベースの UNIQUE 制約（同じ日付＋開始時刻で「予約済み」は1件のみ）で、
   ほぼ同時に2人が送信しても**必ず片方だけ**が成立します

埋まっていた場合は画面にエラーと**空いている時間の候補**を表示し、カレンダーも自動で更新します。

## 7. 異常時のふるまい

無人運営なので、「外部サービスが落ちても予約は失わない」設計にしています。

| 状況 | ふるまい |
|---|---|
| SwitchBot APIが失敗 | 予約は成立。お客様には「パスコードは追ってご連絡します」とメール。管理者へ要対応メール。cronが自動で再発行しパスコードを送付 |
| メール送信に失敗 | 再送キューに入り、cronで再送 |
| スプレッドシートが失敗 | DBには記録済み。cronで転記を再試行 |
| 同じ枠に同時送信 | 片方のみ成立。もう片方にはエラーと代替候補を表示 |
| 連携が3回失敗 | 管理者へ「要確認」メール。管理画面上部にも未処理件数を表示 |

## 8. 設定を変えたいとき

| やりたいこと | 変える場所（`app/config.php`） |
|---|---|
| 30分枠にする | `booking.slot_minutes` を `30`、`start_times` を30分刻みに |
| 定休日を作る | `booking.open_days` から曜日番号を外す（0=日 … 6=土） |
| 何時間前まで受け付けるか | `booking.lead_hours` |
| 何日先まで予約可能か | `booking.horizon_days` |
| 解錠の前後余裕 | `booking.buffer_before` / `buffer_after`（分） |
| アンケートの設問 | `survey` 配列。項目を足すとフォーム・メール・スプレッドシートの列が自動で増えます |

> アンケートの設問を増やした場合、スプレッドシートの見出し行は自動では増えません。
> 管理画面の「スプレッドシート初期設定」をもう一度押すと見出しが更新されます。

## 10. セキュリティ上の注意

- `app` / `bin` / `storage` は `.htaccess` で直接アクセスを禁止していますが、
  **公開フォルダは必ず `public` に設定してください**（ここを間違えると設定ファイルが見えてしまいます）
- パスコードは画面には表示せず、メールでのみお知らせしています
- 管理画面のパスワードは推測されにくいものにし、共有しないでください
- 予約フォームには自動投稿よけと連続送信の制限を入れています
- **GitHubに上げるときは `.gitignore` をそのまま残してください。**
  `app/config.php`（SwitchBotのトークンや管理パスワード）、`storage/` の顧客データと
  Google認証情報が公開されないようにしてあります。
  GitHub Pages はリポジトリ内のファイルを誰でも見られる形で配信するため、
  設定済みの `config.php` を一度でも上げてしまうと、トークンを作り直す必要があります
