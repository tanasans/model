# AI秘書 カイト（日本語音声・ローカルMVP）

Windows PC の Chrome で「会話開始」を押して日本語で話すと、AI が日本語の音声で答える最小構成です。
OpenAI の GA 版 Realtime API（WebRTC）と公式 SDK `@openai/agents/realtime` を使います。

> このフォルダは独立しています。リポジトリ内の他のファイル（モデルルーム予約システム等）には依存も変更もしていません。

### 通信の流れとセキュリティ

1. 「会話開始」→ Chrome がマイク使用の許可を求める。**許可された場合だけ**次へ進む。
2. ブラウザ → ローカルサーバー `POST /api/session`。サーバーは `.env` の APIキーで
   OpenAI の **`POST /v1/realtime/client_secrets`（GA）** を呼び、**有効期限60秒の短命 client secret** を発行してブラウザへ返す。
   通常の APIキーはブラウザに一切渡りません（旧ベータの `/realtime/sessions` は使いません）。
3. ブラウザは短命 client secret で OpenAI と **WebRTC** 接続（`/v1/realtime/calls`）し、音声で会話。
4. 「会話終了」/ 最大時間到達 / エラー / 切断 / タブを閉じる → WebRTC・マイク・音声再生を閉じ、サーバーのセッション枠を解放。

課金の暴走を防ぐしくみ：

| 対策 | 内容 |
| --- | --- |
| 明示的な開始・終了 | ボタン操作でのみ接続。常時待機・自動起動なし |
| 最大継続時間 | 既定 300 秒（`MAX_SESSION_SECONDS`、上限 1800）。ブラウザ側で自動切断し、さらにサーバー側でも期限到達時に OpenAI の通話を切断（hangup API） |
| 同時セッション数 | サーバー全体で同時 1 件のみ（2件目は拒否） |
| 開始の連打防止 | 3 秒以内の再発行は拒否 |
| エラー時切断 | 通信エラー・接続断を検知したら即座に全て閉じる |
| 接続元制限 | サーバーは 127.0.0.1 のみで待ち受け。`Origin` が localhost 以外の要求を拒否（他サイトからの不正発行防止） |

ログ方針：APIキー・短命トークン・音声・会話内容は出力しません（エラーの種類と HTTP ステータスのみ）。
SDK のトレース送信（`tracingDisabled: true`）と音声の履歴保持（`historyStoreAudio: false`）も無効化しています。音声録音の保存機能はありません。

### 使用モデル（2026-11-05 時点、インストールした公式パッケージの型定義で確認）

- 会話モデル：`gpt-realtime-2.1`（`@openai/agents` 0.21.0 の既定値。`.env` の `REALTIME_MODEL` で変更可。安価な `gpt-realtime-2.1-mini` 等も指定可能）
- 入力の文字起こし：`gpt-4o-mini-transcribe`（言語 `ja`）
- 声：`marin`（`REALTIME_VOICE` で変更可）

## 拍手2回で会話を開始する（第2段階）

1. 画面の「拍手待機」スイッチを ON にする（初回はマイク許可を求められます）。
2. 状態が「待機中（手を2回叩くと会話を開始）」になったら、**パン、パン** と手を2回叩く。
3. 「ピロン」と起動音が鳴り、通常の「会話開始」と同じ流れで会話が始まります。
4. 会話が終わると（会話終了ボタン・最大時間・エラー）、自動的に待機中に戻ります。スイッチを OFF にするとマイクを解放します。

- 「会話開始」「会話終了」ボタンはこれまでどおり使えます。
- **待機中は OpenAI に一切接続しません**（料金はかかりません）。音はブラウザ内で判定するだけで、送信・保存しません。
- 会話中は拍手検出を止め、待機用マイクも解放します。
- 拍手で起動したのに **15 秒間話しかけがない場合は自動で終了**します（誤起動による課金を抑えるため）。
- 毎回ページを開いた直後は OFF です（勝手にマイクを使わないため）。感度と間隔の設定はブラウザに保存されます。
- Chrome のタブを開いたままにしておく必要があります。タブを閉じる・PC がスリープすると待機は止まります。

### 判定の仕組み（v3）

1つの大きな音について、次の6項目を調べます。結果は画面の「直近の大きな音」に ✓／✗ と数値・基準つきで表示されます。

| 項目 | 内容 | 主に除外する音 |
| --- | --- | --- |
| 大きさ | ピークが反応ライン（赤線）以上 | 小さな物音・遠くの音 |
| 急な変化 | 直前（7.5〜30ms 前）の平均から何 dB 急に大きくなったか | 徐々に大きくなる音 |
| 立ち上がり | 音の始まりからピークまでの時間 | 話し声 |
| 短さ | ピークの 30〜60ms 後にどれだけ小さくなったか | 話し声・音楽など続く音 |
| 音の高さ | 立ち上がり部分の周波数の重心 | 机に物を置く音・足音 |
| 尖り | 最大振幅 ÷ 平均振幅 | キーボードの「カチッ」という細い音 |

2回の並び方についても確認します。

- 1回目の前 0.3 秒に話し声などの続く音がなく、0.8 秒以内にタイピングなどの鋭い音がない。
- 2回の間隔が 0.12 秒以上、最大間隔以内で、2回の大きさの差が 12dB 以内。
- 2回目の後 0.3 秒以内に3回目の鋭い音がない。

#### v2 で起動しにくかった原因と修正

- **原因1（主因）：拍手の残響の誤認。** 普通の部屋では、拍手の後に部屋の響き（残響）が 0.1〜0.5 秒ほど残ります。v2 はこの響きを「新しい音・立ち上がりが緩やか」と判定し、「途中で別の音があった」として1回目を取り消していました。実機で出ていた2つのメッセージはこれが原因です。合成音での再現で確認しました（残響のない部屋だけ起動し、普通の部屋・響く部屋では0回）。
  **修正：** 拍手の後は「余韻」として扱い、余韻の中からは新しい鋭い音（2回目の拍手）だけを拾います。
- **原因2：立ち上がりの判定。** v2 は「直前 15ms の最小値」との比較だけで判定しており、フレームの区切り方や残響によって実際の拍手まで落としていました。
  **修正：** 直前の平均との比較（急な変化）と、ピークまでの時間（立ち上がり）を分けて評価するようにしました。

#### マイクの音声加工の影響

| 加工 | 拍手への影響 |
| --- | --- |
| ノイズ抑制 | 突発的な短い音を雑音として削るため、拍手が小さく鈍くなる |
| 自動音量調整 | 大きな音の直後に音量を下げるため、2回目の拍手が小さくなる。静かなときは雑音を持ち上げる |
| エコーキャンセル | 音を加工・遅延させる |

拍手検出用のマイクでは、これらをすべてオフにするようブラウザに要求しています。実際にオフになったかどうかは画面のチップ（「自動音量調整 OFF」など）で確認できます。通常の音声会話は、聞き取りやすさのため従来どおりオンのままです。

Windows 側の「オーディオの強化」「音声フォーカス」や、メーカー独自の音声処理（Realtek・Dolby・NVIDIA Broadcast・Windows Studio Effects など）はブラウザから止められません。うまく検出できない場合は、「設定 → システム → サウンド → 入力デバイス（マイク）のプロパティ」でこれらをオフにしてください。

### キャリブレーション（おすすめ）

「キャリブレーション」ボタンを押すと、次の手順で進みます（約30秒）。**各手順は時間で自動的に次へ進みます。完全な無音は不要で、小さな物音があっても最初からやり直しにはなりません。**

1. **環境音（4秒）**：ふだんの部屋の状態のまま待ちます。エアコンやPCファンの音、小さな物音もそのまま測り、次の値を自動で決めます。
   - 環境音の基準値（ノイズフロア）：測定した音量の中央値
   - 環境の小さな音の大きさ
   - 拍手判定しきい値：環境音と小さな音より十分大きいレベル
2. **拍手（最大15秒、5回数えたら次へ）**：1秒ほど間をあけ、ふだん起動するときと同じ位置・強さで1回ずつ拍手します。しきい値に届かない小さな音は拍手として数えず、「無視した回数」として表示します。
3. **声・キーボード（任意、6秒）**：「測る」を押してふだんの声で話すかキーボードを打つと、それと区別できる基準にします。15秒操作がなければ自動で結果へ進みます。
4. **結果**：次のいずれかを選びます。
   - 成功時：「この基準を使う」
   - 拍手を3回以上数えられなかったとき：「環境音の結果だけで試す」（標準の判定に、環境に合わせた反応ラインを組み合わせた基準）
   - どちらの場合も：「手動設定で試す」

測定中も待機中も、画面には「現在の入力」「環境音の基準値」「拍手判定しきい値」と、使用中のマイク名、音声加工（自動音量調整・ノイズ抑制・エコーキャンセル）の**実際の**適用状態が表示されます。

基準はこのブラウザにだけ保存され、送信はされません。「標準に戻す」でいつでも元に戻せます。

### 手動設定

「手動設定」ボタンを押すと、6つの判定基準をスライダーで直接変えられます。変更はすぐに反映されるので、テストモードと「直近の大きな音」の ✓／✗ を見ながら調整してください。キャリブレーションがうまくいかない場合でも、この方法でテストできます。

- 拍手が反応しないとき：「拍手判定しきい値」を下げる。響く部屋では「短さ」も下げる。
- 小さな物音に反応するとき：「拍手判定しきい値」か「環境音からの差」を上げる。
- キーボード音に反応するとき：「尖り（上限）」を下げる。

#### v4 で直したこと（キャリブレーションが進まなかった原因）

- **原因：拍手の測定で、小さな物音まで「拍手」として数えていた。** 特徴を集めるための緩い基準をそのまま使っており、手順1で測った環境音と比べていませんでした。そのため小さな物音で5回分がすぐ埋まり、最後に「拍手0回」で失敗し、やり直すと手順1から始まる、という繰り返しになっていました。合成音（ファン音＋小さなコツコツ音）で再現を確認しました。
  **修正：** 手順1の環境音から「拍手判定しきい値」を決め、それを超える鋭い音だけを数えます。残響を二重に数えないよう、0.3秒以内の音は数えません。
- **騒音レベルの推定：** 従来は「大きな音がない間だけ」更新する方式だったため、小さな音が頻繁にあると正しく更新されませんでした。直近3秒の下位20%の値を使う方式に変更し、瞬間的な音に左右されず、エアコン等の続く音には追従するようにしました。
- **小さな音の直後の拍手：** 小さな音を分析している最中（約0.1秒）に来た拍手を取りこぼしていました。はるかに大きな鋭い音が来たら、そちらを分析し直すようにしました。
- **進行の安定化：** 各手順を音声の時間で自動的に進めるようにしました。マイクから音声が届かない場合（2.5秒）は、エラーとして表示します。

### テストモード（料金なしで検知率を確認）

「テストモード」にチェックを入れると、拍手2回を検知しても会話は始めず、起動音を鳴らして回数を数えるだけになります。OpenAI に接続しないので料金はかかりません。**20回叩いて18回以上検知できるか**の確認に使ってください。

### 感度・間隔の調整

- **感度（1〜10、既定 5）：** 反応しない場合は上げ、誤反応する場合は下げてください。6項目すべての基準がまとめて緩く／厳しくなります。
- **2回の間隔（最大、0.30〜1.00 秒、既定 0.60 秒）：** ゆっくり叩く場合は長めにしてください。
- 起動しないときは、まず「直近の大きな音」で ✗ が付いた項目と、判定の履歴に表示される取り消し理由を確認してください。

### 既知の制約

- キーボードを「2回だけ」打って止まると、拍手と判定されることがあります。合成音の最悪ケースでは、標準の基準で3分間に14回でした（キャリブレーションの手順3でキーボード音を登録すると0回）。拍手で起動した会話は、15秒話しかけがなければ自動で終了します。
- Chrome のタブを開いたままにする必要があります。スマホのバックグラウンド動作は対象外です。

## 外部情報の表示（第1弾：時間別天気予報）

会話中に「明日の大阪の天気は？」「札幌の明後日の天気を見せて」などと聞くと、KAITO が天気を取得して音声で答え、中央の AI コアが**時間別天気予報**の表示に切り替わります。「元の画面に戻して」と言うか、表示の「◀ 戻る」を押すと、司令室画面に戻ります。

- **表示内容**
  - 24 時間分の気温・降水確率・天気アイコン
  - 最高・最低気温、最大降水確率
  - 地点（都道府県・緯度経度）、情報源（Open-Meteo・CC BY 4.0）、取得日時
- **データの扱い**
  - 取得した 1 時間ごとの元データは、ブラウザ内の予報ストア（`src/tools/forecastStore.ts`）に保存します。画面も AI も、この同じデータを参照します。
  - AI には 24 時間分すべてを渡します（間引きません）。「14時の気温は？」「13時から17時まで」「画面の天気を詳しく」などの質問には、AI が `get_weather_hours` ツールで取得済みデータの該当時刻を参照して答えます（再取得しません）。
  - 同じ都市・日付の再質問は、10 分間は取得済みデータを再利用します。
  - 時刻は予報地点の現地時刻です。
  - 取得できなかった値は「—」（AI には「データなし」）とし、前後の値などから推測で補いません。
  - 場所が見つからない場合や取得に失敗した場合は、そのまま伝えます（別の都市で代用しません）。
- **都市名**
  - Open-Meteo は「大阪」のような日本語の短い地名を検索できないことがあります（「大阪市」や「Osaka」なら見つかる）。
  - そのため「話された名前 → 〜市 → ローマ字表記（AI が付ける）」の順に探し、見つかった地点を画面に表示します。
- **日付**：今日・明日・明後日、または日付指定（今日から 15 日先まで）。過去と範囲外は「取得できません」と答えます。
- **料金・利用条件**
  - Open-Meteo は API キー不要・非商用無料です。IP アドレスごとに 1 日の利用上限があり、超えると「利用上限に達しました」と表示します（同じ地点・日付は 10 分間キャッシュ）。
  - 取得はローカルサーバー経由で、1 分あたり 30 回までに制限しています。
  - 会話自体の料金・300 秒上限・同時接続 1 件は従来どおりで、待機中は外部に接続しません。

## 調査報告：テレビ音声で会話が途切れる問題

**現在の設定**（既定から変更していません）

| 項目 | 現在値 | 影響 |
| --- | --- | --- |
| 発話の区切り（VAD） | `semantic_vad`、積極性 `medium` | 発話内容から言い終わりを判断 |
| 割り込み（interrupt_response） | 未指定＝API の既定（**話し始めの音で KAITO の返答を止める**） | テレビの声も「話し始め」と判定されると、KAITO の返答が途中で止まり、テレビの声に返事をしようとする |
| OpenAI 側の雑音低減（noise_reduction） | なし | テレビ音声をそのまま受け取る |
| ブラウザ側の音声加工（会話用マイク） | エコーキャンセル・ノイズ抑制・自動音量調整 ON | KAITO 自身の声は消せるが、テレビの声（人の声）は消せない |

**原因の見立て**：テレビの人の声は、VAD から見ると「ユーザーの声」と区別できません。割り込みが有効なため、テレビの声で返答が止まり、会話が途切れます。

**画面から切り替えられるプリセット（第1段階で追加）**：設定アイコン →「音声」タブ →「周囲の音（テレビ）対策」。次の新しい会話から適用され、ブラウザに保存されます。既定は「標準」で、従来と同じ内容を送ります（自動テストで確認）。

| プリセット | 送る内容（.env の設定に重ねる） | 副作用 |
| --- | --- | --- |
| 標準（従来どおり） | .env の設定そのまま | なし |
| テレビ対策・弱 | ＋ 雑音低減 `far_field` | ほぼなし（効果は限定的） |
| テレビ対策・強 | ＋ 雑音低減 `far_field` ＋ `interrupt_response=false` | KAITO の返答中に声で割り込めない（止めたいときは「会話終了」） |

VAD の方式・しきい値（下の 3）は副作用が大きいため、プリセットには含めず `.env` のみで調整します。詳しい比較と実機での確認手順は [docs/STAGE1.md](docs/STAGE1.md)。

**改善候補**（効果が大きく副作用が小さい順。2・4 は上のプリセットでも試せます）

1. **マイクの工夫（設定変更なし）**：ヘッドセットや口元の指向性マイクにする、テレビから離れる、話すときはテレビの音量を下げる。最も確実です。
2. `INPUT_NOISE_REDUCTION=far_field`（PC 内蔵マイク）／`near_field`（ヘッドセット）：OpenAI 側で雑音を弱めます。テレビの声への効果は限定的ですが、副作用は小さいです。
3. `VAD_MODE=server` と `VAD_THRESHOLD_PERCENT=65`〜`75`：小さめの音（離れたテレビ）を発話と判定しにくくします。上げすぎると自分の声も拾いにくくなります。
4. `VAD_INTERRUPT_RESPONSE=false`：テレビの声で KAITO の返答が止まらなくなります。ただし声で割り込めなくなるため、止めたいときは「会話終了」ボタンを使います。
5. 将来案：押している間だけ話す「プッシュ・トゥ・トーク」方式（未実装）。

## KAITO 設定（KAITO.md）

KAITO の話し方・禁止表現・起動時の挨拶などは、Markdown のファイルで管理します。

| ファイル | 内容 | GitHub |

## 声で会話を終える・待機を止める

- 会話中に「終わって」「もうええよ」「以上」などと言うと、KAITO が短い別れの一言を言い、**再生し終わってから**自動で切断します。終わりたいのかどうか曖昧なときは、KAITO が「終わってええ？」などと確認します。
- 「終わって、待機も止めて」「もう寝てええよ」のように言うと、会話の終了と同時に **音声待機・拍手待機も OFF** になります（会話が終わっても待機に戻りません）。
- 待機中（会話していないとき）に声で待機を OFF にする機能はありません。テレビなどで勝手に OFF になるのを防ぐためです。待機中はスイッチで OFF にしてください。
- 別れの一言が始まらない場合は 5 秒後、長すぎる場合も 15 秒後には必ず切断します。「会話終了」ボタン・300 秒の上限・無言 15 秒の自動終了は、これまでどおりです。
- 仕組み：天気と同じ Function Calling のツール `end_conversation`（引数 `stop_standby`）。切断のタイミングは `src/endAfterReply.ts`。

## 声の選択と試聴

- 設定アイコン →「音声」タブのドロップダウンから、Realtime API で使える 10 種類の声を選べます：marin（従来の既定・比較用）、cedar・ash・echo（優先候補）、ballad・verse・sage・alloy・coral・shimmer。一覧は openai SDK の型定義で確認しました。
- 「▶1〜3」で、次の固定の短い文を、会話と同じ Realtime API・同じモデル・同じ話し方の指示で試聴できます。
  - 「はい、カイトです。」
  - 「明日は晴れるみたいじゃけぇ、傘はいらんと思うよ。」（広島弁の確認用）
  - 「今の状況を見てみたんじゃけど、大事な点が二つあるんよ。」（広島弁の確認用）
- 「最初の音まで」の時間（応答速度の目安）も記録・比較できます。
- **試聴は 1 回ごとに API 料金がかかります**（短い文 1 回で数円程度の目安。最新の料金表で確認してください）。
  - 料金を抑える仕組み：固定の文のみ、同時に 1 件、4 秒以上の間隔、会話中は不可、出力上限・20 秒の時間切れあり。
- 「採用」を押すまで声は変わりません（既定は .env の `REALTIME_VOICE`、通常 marin）。採用した声は次の新しい会話から使われ、ブラウザに保存されます。
- 話し方の指示は「KAITO 基本設定」に基づきます（`shared/assistant.ts` の `ASSISTANT_INSTRUCTIONS`）。役割、話し方（**広島弁**・1〜3文・軽いユーモア）、使用しない前置き、回答ルール、会話スタイル、記憶とプライバシーの各項目を含みます。特定の人物やキャラクターの模倣はしません。
- 会話が始まると、KAITO が最初に「はい、カイトです。」と言います（接続直後に、この一言だけを話す専用の指示で応答を 1 回作ります。数秒分の音声出力の料金がかかります）。

### 仕組みとプライバシー

| 段階 | 処理する場所 | OpenAI への送信 |
| --- | --- | --- |
| 待機中の呼びかけ検出 | この PC のブラウザ内（Vosk、WebAssembly） | **なし（API 料金なし）** |
| 「カイト」を検知した後の会話 | OpenAI Realtime API（従来どおり） | あり |

### 誤起動を防ぐ判定

認識結果（確定したものだけ）に対して、次をすべて満たすときだけ起動します。画面の「直近の呼びかけ」に ✓／✗ で表示されます。

| 項目 | 内容 | 主に防ぐもの |
| --- | --- | --- |
| 言葉の位置 | 認識結果の先頭が「カイト」（または「ねえ カイト」） | 文の途中の「カイト」 |
| 信頼度 | 認識エンジンの信頼度が基準以上（感度で変化） | 似た言葉（バイト等） |
| 長さ | 0.18〜1.0 秒 | 雑音 |
| 前の静けさ・後の静けさ | 呼びかけの直前・直後が静か | **テレビ・会話の途中** |
| 続く言葉 | 後ろに別の言葉が続かない | 「カイトが…」など |

- 「ねえ、カイト」用の認識器には「ライト」「バイト」「ナイト」「サイト」「回答」などの似た言葉も候補として登録し、誤認識をそちらに吸収させます。
- 「両方」モードで感度を 1〜3 にすると、似た言葉側の認識器が同じ時間に「バイト」等と聞き取った場合も単独の「カイト」を採用しません（誤起動は減るが取りこぼしが増える）。
- 雑音低減（任意）：「サー」という定常的な雑音が多い環境向け。普通の部屋では逆に認識率が下がることがあったため、既定は OFF です。

### 呼びかけの言葉と感度

- 呼びかけの言葉：「両方（既定）」「ねえ、カイトのみ（誤起動が最も少ない）」「カイトのみ」から選べます。
- 感度（1〜10、既定 5）：上げると検出しやすく、下げると誤起動が減ります。
- 「テストモード」で、会話を始めずに検知回数だけ数えられます（料金なし）。20 回呼んで 18 回以上を目安に調整してください。

| 両方（既定） | 33/90（37%） | 54/90（60%） | 3 回 | 0 回 | 0 回 |
| ねえ、カイトのみ | — | 54/90（60%） | 1 回 | 0 回 | 0 回 |

- **目標（20 回中 18 回＝90%）には、合成音声では届いていません。** 合成音声は機械的な声のため、認識エンジンの学習データ（人の声）と異なり、実際の声とは結果が大きく変わる可能性があります。必ず実機で「テストモード」を使って測定してください。
- 単独の「カイト」は 3 音と短く、似た言葉と区別しにくいため、「ねえ、カイト」の方が検出率・誤起動の両面で有利でした。
- 既知の誤起動：「カイトウ（怪盗）」は「カイト＋ウ」のため単独モードでは起動することがあります（「ねえ、カイト」モードでは起動しません）。
- 実機で 18/20 に届かない場合の次の候補：Picovoice Porcupine（専用のウェイクワードエンジン）への切り替え。アカウント登録と利用規約の確認が必要なため、導入前にご相談します。

## 返答の速さと発話の区切り（VAD）

返答までの間を短くするため、次を調整しました（`.env` で変更可能）。

- **推論量 `REASONING_EFFORT=low`**：`gpt-realtime-2` 系は推論（考える処理）を行うモデルです。推論量を抑えると返答の開始が速くなります。モデルが受け付けない場合は自動的に設定を外して従来どおり接続します。
- **発話の区切り `VAD_MODE=semantic`（既定）**：発話の内容から「言い終わったか」を判断する方式です。言いよどみや「〜なんだけど、」のような途中の間で割り込みにくいのが利点です。
  `VAD_EAGERNESS` は low / medium / high の順で速く返答しますが、言い終わりが曖昧なときの最大待ち時間は low 8 秒・medium 4 秒・high 2 秒です（OpenAI SDK の仕様説明より）。**途中で割り込まれないことを優先して既定は medium** にしています。
- それでも遅いと感じたら、次の順で試してください（1 つずつ変えてサーバーを再起動）。
  1. `VAD_EAGERNESS=high`（速くなるが、考えながら話すと割り込まれることがある）
  2. `VAD_MODE=server` と `VAD_SILENCE_MS=700`（無音 0.7 秒で言い終わりと判定。600 にするとさらに速いが割り込みやすい）
- 指示文も「結論から先に、ふだんは1〜2文で」に変更したため、返答の長さも短くなります。

## Windows での使い方

### 1. Node.js の確認

PowerShell を開き、次を実行します。`v20.19` 以上（推奨 v22 LTS 以上）が表示されれば OK です。

```powershell
node -v
npm -v
```

表示されない・古い場合は https://nodejs.org/ から LTS 版をインストールしてください。

### 2. 依存パッケージのインストール

```powershell
cd <このリポジトリの場所>\personal-voice-assistant
npm install
```

### 3. 環境変数の設定

```powershell
copy .env.example .env
notepad .env
```

メモ帳で `OPENAI_API_KEY=` の右側に、OpenAI の管理画面（https://platform.openai.com/api-keys ）で作成した APIキーを貼り付けて保存します。
**APIキーはチャットやメール、Git に貼らないでください。** `.env` は `.gitignore` 済みです。

### 4. 起動

```powershell
npm run dev
```

`listening on http://127.0.0.1:8787` と `Local: http://127.0.0.1:5173/` が表示されたら起動完了です。

### 5. Chrome で確認

1. Chrome で **http://localhost:5173** を開く（開けない場合は http://127.0.0.1:5173 ）。
2. 「サーバー：起動中・APIキー設定済み」と表示されることを確認。
3. 「会話開始」を押し、マイクの許可を求められたら「許可する」。
4. 状態が「接続中（話しかけてください）」になったら日本語で話しかける（例：「こんにちは、今日の予定を立てるコツを教えて」）。
5. AI が日本語の音声で答え、画面に文字起こし（取得できた分のみ）が表示されます。
6. 「会話終了」を押すと、マイク（タブのマイクアイコン）と接続が閉じます。再度「会話開始」で再開できます。

APIキー未設定でも画面は開けます。その場合「会話開始」を押すとマイク許可の後に
「サーバーに OPENAI_API_KEY が設定されていません」と表示され、接続成功のようには見えません。

### 6. 停止

`npm run dev` を実行している PowerShell で **Ctrl + C** を押します（「バッチ ジョブを終了しますか」と聞かれたら `Y`）。

### その他のコマンド

```powershell
npm run typecheck   # 型チェック（クライアント・サーバー・テスト）
npm test            # 拍手検出・音声呼びかけ判定のテスト

```

## 想定料金と API 課金の注意（必ずお読みください）

- Realtime API は **音声の入力・出力トークン量に応じた従量課金** です。音声は文字より単価が高く、話す時間・AI が話す時間に比例して増えます。
  文字起こし（`gpt-4o-mini-transcribe`）も別途課金されます。
- 目安（概算・未検証）：過去の GA 版 `gpt-realtime` の公開単価から計算すると、**会話 1 分あたりおおむね数円〜数十円程度**になり得ます。
  実際の単価はモデル（`gpt-realtime-2.1` / mini 等）や会話内容・長さで変わります。**最新の正確な単価は必ず公式の料金ページ（https://openai.com/api/pricing/ ）で確認してください。**
  - 例：最大 300 秒の会話を 1 日 10 回行うと、1 日最大 50 分の通話になります。
- **このアプリ側の制限だけでは課金上限になりません。** OpenAI の管理画面（https://platform.openai.com/ の Settings → Limits / Billing）で
  **月の予算上限（Budget）・通知（Usage alerts）を必ず設定**してください。プリペイド（Credit）残高を少額にしておくのも有効です。
- 会話後は必ず「会話終了」を押してください（押し忘れても最大継続時間で自動切断されます）。
