## 2. テレビ音声への対策

**原因**：テレビの人の声は、VAD から見るとユーザーの声と区別できません。API の既定では話し始めの音で返答を止める（`interrupt_response`）ため、KAITO の返答が途中で止まります。

**今回の対応**：「音声」タブ →「周囲の音（テレビ）対策」で、3 段階を切り替えて比較できるようにしました。既定は「標準」で、送る内容は従来と完全に同じです（自動テストで確認）。

| プリセット | 雑音低減 | 返答中の割り込み | VAD | 想定効果 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| 標準 | .env どおり（既定なし） | .env どおり（既定は止める） | .env どおり | 従来どおり | なし |
| テレビ対策・弱 | `far_field` | .env どおり | .env どおり | 小さめの周囲音を弱める | ほぼなし |
| テレビ対策・強 | `far_field` | 止めない（`false`） | .env どおり | テレビの声で返答が途切れなくなる | 声で割り込めない。返答後にテレビの声へ応答する可能性は残る |

- VAD の方式・しきい値（`VAD_MODE=server`、`VAD_THRESHOLD_PERCENT=65〜75`）は自分の声も拾いにくくなるため、プリセットに含めず `.env` だけで調整します。プリセットは .env の設定に重ねて適用されます。
- 最も確実なのは、ヘッドセットや指向性マイクを使うことです。
- 画面で選んだ値は、サーバー側でも許可リストで検証します（不正な値は「標準」として扱う）。

## 3. 日本語音声（外国人のような抑揚）

**見立て**：Realtime API の声は多言語に対応しています。指示が無いと、英語のような強弱の抑揚や語尾の上がりが出ることがあります。声そのものを作り替えることはできないため、次の 3 つを組み合わせて検証します。

> 追記（ブランチ `claude/kaito-persona`）：「KAITO 基本設定」により会話は**広島弁**に変更しました。アクセントの指示も「広島で育った話者の自然なアクセント」に置き換えています。英語風の抑揚を避ける指示はそのまま残しています。

1. **話し方の指示**（第1段階時点）：「東京の標準語を母語とする話者の自然なアクセントとイントネーション」「英語のような強弱の抑揚・単語ごとの上げ下げ・疑問文以外の語尾の上がりを避け、文末を自然に下げる」「外来語・数字も日本語読み」「句読点で短く間を取る」。特定の声優やキャラクターの模倣はしません。
2. **声の比較**：試聴で marin・cedar・ash・echo を同じ文で聞き比べます。試聴は会話と同じモデル・同じ指示を使うため、今回の指示の効果も試聴で確認できます。
3. **話す速さ**（今回追加）：0.85／0.90／0.95／1.00。既定は 1.00（従来どおり）。試聴にも反映されます。速度は生成後の調整なので、抑揚そのものは指示と声の選択で改善します。

## 5. Windows 実機での確認手順

1. ZIP を展開した `personal-voice-assistant` で `npm.cmd install` を実行し、続けて `npm.cmd run dev` を実行します。Chrome で http://localhost:5173 を開きます（`.env` は前の版からコピー）。
2. **設定の復元**：設定アイコン →「音声」で、話す速さを 0.95、テレビ対策を「弱」にします。F5 で再読み込みし、同じ値が残っていることを確認します。拍手・呼びかけの設定も残っていることを確認します。
3. **待機中は料金がかからないこと**：音声待機と拍手待機を ON にして 1〜2 分置きます。OpenAI の Usage 画面で、その間の Realtime の利用が増えていないことを確認します。
4. **日本語の聞こえ方**：試聴文「承知しました。確認した情報から順に報告します。」を、marin・cedar・ash・echo、速さ 1.00 と 0.95 で聞き比べます。各 1 回で数円程度かかります。語尾が上がる、単語ごとに抑揚が付くなどの違和感を記録し、最も自然な声を採用します。
5. **テレビ対策**：テレビを普段の音量で付けたまま「明日の大阪の天気は？」と聞き、KAITO の返答が途中で止まるかを、「標準」「弱」「強」の順に 3 回ずつ確認します（例：止まった回数 / 3）。
6. **天気の精度**：「明日の大阪の14時の気温は？」「15時の降水確率は？」「13時から17時まで1時間ごとに教えて」「画面に表示している天気を詳しく説明して」と聞き、画面の数値と一致するかを確認します。
7. **会話の上限**：会話開始から 300 秒で自動終了することを確認します。会話終了後にマイクのランプが消えることも確認します。

## 7. 次の「長期記憶（SQLite）」に向けた設計上の注意

今回は実装していません。

1. **保存場所**：PC 内のローカルファイルだけに保存します（例：`personal-voice-assistant/data/kaito.sqlite`）。`data/` は `.gitignore` に入れ、GitHub には絶対に含めません。読み書きはサーバー側だけで行い、ブラウザには必要な結果だけを返します。
2. **何を覚えるかを明示する**：会話の録音や全文の文字起こしを自動で保存しない方針を基本にします。ユーザーが「覚えて」と言ったこと、または確認済みの事実だけを保存します。保存時には「〜を覚えました」と声と画面で伝えます。
3. **削除と確認**：「忘れて」で削除でき、画面から一覧の表示・削除・全消去ができるようにします。削除は物理削除とし、`VACUUM` の実行も検討します。
4. **秘密情報を入れない**：API キー、パスワード、口座番号、カード番号などは保存を拒否します（パターン検査）。ログに記憶の内容を出しません。
5. **記憶と外部データを分ける**：天気・JRA-VAN・株価などの取得データは「その時点の事実」なので、出典と取得時刻付きのキャッシュとして別テーブル（または別ファイル）に置きます。長期記憶（ユーザーの好みや予定）とは混ぜません。AI に渡すときも、どちらの情報かを区別します。
6. **スキーマの版管理**：`schema_version` テーブルと移行処理を最初から用意します。localStorage の `.v1`／`.v2` と同じ考え方です。
7. **AI に渡す量を絞る**：全記憶を毎回指示に入れると料金と誤答が増えます。関連する記憶だけを検索するツール（例：`recall_memory`）を、既存のツール基盤（`server/tools` の `DataTool`）に追加する形にします。
8. **書き込みは確認付き**：AI が勝手に記憶を書き換えないように、保存と削除はツール経由に限定し、件数と頻度の上限を設けます。売買・送金などの実行操作は、記憶機能からも行いません。
9. **端末間の共有（第6段階）**：同期する場合は暗号化を前提とし、記憶の範囲（どの端末で何を見られるか）を設計してから実装します。
10. **バックアップ**：SQLite ファイルのバックアップ手順（コピーのみ）と、復元時の版の確認を用意します。
